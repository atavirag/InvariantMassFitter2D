# D Meson Pair Analysis

Complete C++/Python framework for 2D invariant mass fitting and visualization of D meson pairs.

## 📁 Project Structure

```
your-analysis/
├── src/              # C++ source code (version controlled)
├── build/            # Build artifacts (gitignored)
├── data/             # ROOT data files (gitignored)
├── plots/            # Generated plots (gitignored)
├── python/           # Python scripts (version controlled)
├── scripts/          # Automation scripts (version controlled)
├── docs/             # Documentation (version controlled)
├── Makefile          # Build system
├── requirements.txt  # Python dependencies
└── .gitignore        # Git ignore rules
```

### What Goes Where?

| Directory | Contents | Git? | Purpose |
|-----------|----------|------|---------|
| `src/` | `.h`, `.cxx` files | ✅ Yes | Source code |
| `build/` | `.so`, `.d`, `.o`, executables | ❌ No | Compiled artifacts |
| `data/` | `.root` files | ❌ No | Analysis outputs |
| `plots/` | `.pdf`, `.png` | ❌ No | Visualizations |
| `python/` | `.py` files | ✅ Yes | Python scripts |
| `scripts/` | `.sh` files | ✅ Yes | Automation |
| `docs/` | `.md` files | ✅ Yes | Documentation |

## 🚀 Quick Start

### First Time Setup

```bash
# 1. Organize existing files (if needed)
chmod +x setup_project.sh
./setup_project.sh

# 2. Build C++ code
make

# 3. Install Python dependencies
pip install -r requirements.txt

# 4. Run complete analysis
cd scripts
./run_complete_analysis.sh
```

### Regular Usage

```bash
# Build and run
make run

# Generate plots
python python/visualize_with_fits.py \
    --workspace data/fit_workspace.root \
    --os-file data/os_pairs.root \
    --ls-file data/ls_pairs.root \
    --output-dir plots/
```

## 🔧 Makefile Targets

```bash
make           # Build executable
make run       # Build and run analysis (outputs to data/)
make clean     # Remove build artifacts only
make cleandata # Remove ROOT files from data/
make cleanplots# Remove plots
make cleanall  # Remove everything generated
make info      # Show build configuration
make help      # Show all targets
```

## 📋 File Organization Rules

### ✅ DO Commit (Keep in Git)

- **Source code**: `src/*.{h,cxx}`
- **Python scripts**: `python/*.py`
- **Build config**: `Makefile`, `requirements.txt`
- **Documentation**: `docs/*.md`, `README.md`
- **Scripts**: `scripts/*.sh`
- **Git config**: `.gitignore`

### ❌ DON'T Commit (Gitignored)

- **Build artifacts**: `build/*.{so,d,o}`, executables
- **Data files**: `data/*.root` (usually large)
- **Plots**: `plots/*.{pdf,png}` (can be regenerated)
- **Temp files**: `*.tmp`, `*~`, `*.log`
- **IDE files**: `.vscode/`, `.idea/`, `.DS_Store`

### 🤔 Maybe Commit (Case by case)

- **Small test data**: If < 10 MB, could keep in `data/test/`
- **Reference plots**: Key results for comparison
- **Config files**: Analysis-specific configurations

## 🎯 Why This Organization?

### Benefits

1. **Clean separation**: Source vs. generated files
2. **Easy builds**: `make clean` removes only build files
3. **Git-friendly**: `.gitignore` handles everything
4. **Reproducible**: Anyone can clone and build
5. **Professional**: Industry-standard layout

### Build Artifacts Explained

| File Type | What is it? | Keep? |
|-----------|-------------|-------|
| `*.o` | Object files from compilation | ❌ Build |
| `*.so` | Shared libraries | ❌ Build |
| `*.d` | Dependency files (auto-generated) | ❌ Build |
| `*_cxx.{so,d}` | ROOT dictionary files | ❌ Build |
| Executable | Final compiled program | ❌ Build |

All these are regenerated by `make`, so never commit them!

```bash
# Verify nothing large is committed

# Check for accidental commits
git ls-files | grep -E '\.(root|so|o|d)$'
# Should return nothing!
```

### Change Output Directories

Edit `Makefile`:
```makefile

PLOTDIR = my_plots_folder
```

### Keep Test Data in Git

Edit `.gitignore`:
```bash
# Ignore all .root files
data/*.root

# Except test files
!data/test_*.root
```

## 💡 Pro Tips

1. **Before building**: `make clean` to ensure fresh build
2. **Large datasets**: Consider symlinking `data/` to scratch space
3. **Backup**: Data files can be large, backup separately
4. **Plots**: Regenerate them, don't store in git
5. **Collaboration**: Share only source code, others rebuild
